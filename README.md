# 经营主体有序退出

本项目服务于处理长期未经营主体的退出、异议和恢复程序。仓库保存领域资料、交换契约和可运行的服务入口，便于参与方在同一语义下协作。

## 领域事实

- 监管部门将畅通长期未经营主体退出渠道
- 改革兼顾降低制度成本与有序退出
- 市场治理强调有进有出
- 批量注销不得伤及债权人与真实经营者

## 领域核心（`src/domain/`）

以事件溯源方式维护程序时间线：年报、经营迹象、联系记录、税务社保状态、债权申报、司法限制、公告与异议均为时间线事件。

- `case.js` — 案件聚合：立案（主体类型与适用法律按申请时版本快照）、事件应用、程序路径转移守卫、结论重建
- `machine.js` — 程序状态机：状态秩单调递增，迟到事件不得倒退案件
- `announcement.js` / `calendar.js` — 公告期计算：补正与诉讼保全期间中止，届满日跨周末与法定节假日顺延至下一工作日
- `claims.js` — 债权申报：同一债权人同一债权依据只登记一次，重复申报不多占金额
- `law.js` — 法律版本表：按申请日解析适用版本
- `access.js` — 时间线投影：敏感举报仅向经办角色开放
- `notice.js` — 通知同源派生：申请人与利害关系人获得一致的期限与理由

### 程序路径与转移

简易退出、强制退出、主动注销、歇业恢复之间的转移由显式守卫判定，拒绝时给出理由码：

- 主动注销 → 简易退出：无未结债权、无欠税欠保、无法院限制、主体类型适格
- 简易退出 → 主动注销：异议成立或发现未结债权
- 任意路径 → 强制退出：地址失联、长期未年报且无经营迹象三者齐备
- 受理前 → 歇业；歇业 → 恢复经营（程序终止）

退出结论可由全部通知、异议与清算证据重放重建（`rebuildConclusion`），与增量维护结果一致，与事件到达顺序无关。

## 目录说明

- `contracts/` 保存交换数据的结构约定（领域上下文、时间线事件信封）。
- `fixtures/` 提供去标识的领域样例（领域上下文、案件时间线）。
- 源码目录提供资料读取与健康检查入口。
- `test/` 核对领域资料与领域规则。

## 本地检查

运行 `npm test` 可以检查当前资料与服务入口。

服务入口：`node src/server.js`，提供 `/health`、`/context`、`/conclusion`（由样例时间线重建的退出结论）。
